# ADR 0002: GitHub Rulesetでmainブランチを保護する

- 状態: 採用
- 日付: 2026-07-26

## 背景

`main` へのpushで本番デプロイが始まるため、直接pushや検証不足の変更はそのまま本番環境に影響する。一方、このリポジトリは管理者1名で運用しており、第三者の承認を必須にすると通常の変更をマージできない。

Dependabotを含む複数のPull Requestが並行するため、必須チェックに対して常に最新の`main`を要求すると、他のPull Requestがマージされるたびに更新と再実行が発生する。保護強度と一人運用の継続性を両立する必要がある。

## 決定

GitHubリポジトリに、`main` だけを対象とするActive状態のブランチルールセット `main ブランチ保護` を作成する。

ルールセットは次を必須とする。

- 変更はPull Request経由とし、`main`への直接pushを許可しない。
- 承認レビュー数は0件とする。
- 未解決のレビュー会話が残るPull Requestはマージしない。
- GitHub Actionsが報告する `check` と `e2e` を必須ステータスチェックとする。
- 線形履歴を必須とし、merge commitを使用しない。
- force pushと `main` の削除を禁止する。

管理者にはPull Request経由の場合だけバイパスを許可する。CI障害や保護設定の不備から復旧できる経路を残しつつ、直接pushによる通常運用は認めない。

必須チェックには最新の`main`を要求しない。並行するPull RequestごとのCI再実行を抑えるためである。並行変更の競合が問題になった場合は、マージキュー導入と同時に再検討する。

## 見送るルール

以下は現時点では強制しない。

- 署名付きコミット: jujutsuの署名とGitHubでの検証を別工程で導入してから再検討する。
- デプロイ成功: 現在の本番デプロイは`main`へのマージ後に始まるため、マージ前の条件にしない。
- コードスキャン: CodeQLを導入し、安定して結果が生成されてから必須化を再検討する。
- コミットメタデータ制約: Dependabotのコミットと日本語件名に安全に共通適用できる制約がないため導入しない。
- `main`の作成制限: 既存の`main`の削除自体を禁止するため導入しない。

## 影響

通常の変更はPull RequestとCIを経由し、本番デプロイ元の履歴は直線に保たれる。一方、必須チェックは最新の`main`との組み合わせを常に再検証するものではない。マージ直後に競合が判明するリスクは、並行開発の待ち時間を減らすために受容する。
